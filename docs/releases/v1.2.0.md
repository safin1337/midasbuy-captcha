## Run the solver

From the repository root in PowerShell:

```powershell
.\.venv\Scripts\python.exe '.\Midasbuy Captcha Solver\engine\bridge.py'
```

Load `Midasbuy Captcha Solver/dist` as an unpacked extension. The engine prints a
temporary connection code; keep it local and enter it into the extension. Choose
the format, mark the full puzzle dialog, connect, analyze, review and solve once.
Restart the engine and reload the extension when upgrading from earlier local
development builds. Existing browser capture settings are not migrated or modified.

Format A uses an initial screenshot plus live DOM piece geometry and optional
readable sprite pixels. It holds the pointer across three movements and remeasures
between them. Manual centers retain manual provenance. Format B sends the proposed
three selections followed by OK. There are no automatic retries.

Actual attempts write independent `trial1`, `trial2`, etc. folders under
`Midasbuy Captcha Solver/Format_A/trial` and `Format_B/trial`. Their screenshots,
positions, guidance and outcome are local runtime data, excluded from the release.

## Reproduce validation

Python detector and engine:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s .\Format_A -p "test_*.py" -v
.\.venv\Scripts\python.exe -m unittest discover -s '.\Midasbuy Captcha Solver\engine' -p "test_*.py" -v
.\.venv\Scripts\python.exe .\Format_B\test_contour_points.py
.\.venv\Scripts\python.exe .\Format_B\test_input19_regression.py
```

Solver extension (inside `Midasbuy Captcha Solver`):

```powershell
npm.cmd ci
npx.cmd playwright install chromium
npm.cmd test
npm.cmd run build
npm.cmd run test:browser
npm.cmd run test:visual
```

The browser fixture uses test port 18765, independently of a user engine on 8765.
It exercises real browser input in local nested cross-origin frames with known or
recorded analysis results. Local tests cover DOM/sprite extraction, both format
switches, ordered clicks and confirmation, smooth held motion, manual points,
trial logging, stale-proposal rejection and Stop/close release handling. Visual
checks exercise 390, 1440 and 1728 CSS-pixel widths without external capture services.

The unchanged data extractor retains its own unit and capture integration checks.
The release validation report is `validation-v1.2.0.json` beside these notes.

## Limits

Local fixture success and saved-image review do not establish live provider
acceptance or universal recognition accuracy. The known Format B input46 candidate
localization defect is retained. Ambiguous images remain uncertain, and protected
or unexposed sprites use image evidence. Timing watchdogs request release but cannot
guarantee delivery to a frozen or disconnected browser. Analysis and post-release
file saving are outside the ten-second held-drag target.

All dependencies and browser binaries are installed locally for development;
runtime profiles, engine output, pairing codes and trial data are not published.
